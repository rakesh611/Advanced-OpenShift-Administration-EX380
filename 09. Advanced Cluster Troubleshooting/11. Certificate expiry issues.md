# Certificate Expiry Issues in Advanced Cluster Troubleshooting

**Track:** Advanced OpenShift Administration  
**Topic:** Certificate expiry issues  
**Audience:** Senior OpenShift / Kubernetes administrators, SREs, and platform engineers  
**Experience level:** 10+ years Linux/Kubernetes/OpenShift operations  

---

## 1. Executive Summary

Certificate expiry in OpenShift is a cluster-critical troubleshooting area because TLS protects almost every control path:

- `oc` and console access to the Kubernetes API.
- API server to kubelet communication.
- Kubelet node bootstrap, client authentication, and serving endpoint.
- etcd peer, server, client, and metric traffic.
- Router / Ingress certificates for application routes.
- OAuth, console, registry, monitoring, logging, webhooks, aggregated APIs, and Operators.
- External dependencies such as LDAP, OIDC, proxy, external registry, Git, Vault, and corporate PKI.

The most important senior-admin rule is:

> First identify whether the failing certificate is **OpenShift system-managed** or **user/external-managed**. Do not manually replace system-managed OpenShift certificates unless the official procedure requires it.

Many internal OpenShift certificates rotate automatically, but user-provided API certificates, custom ingress wildcard certificates, route certificates, proxy/custom CA bundles, external registry certificates, LDAP/OIDC endpoint certificates, application certificates, and some third-party Operator webhook certificates remain the administrator's responsibility.

## 2. High-Level Certificate Architecture

```text
External clients
  |-- API certificate: api.<cluster>.<base_domain>:6443
  |-- Ingress/default wildcard certificate: *.apps.<cluster>.<base_domain>
  |-- Route-specific certificates

Control plane
  |-- kube-apiserver certificates
  |-- kube-controller-manager certificates
  |-- kube-scheduler certificates
  |-- aggregated API client certificates
  |-- service-ca certificates
  |-- OAuth/console/registry internal trust

Nodes
  |-- kubelet client certificate
  |-- kubelet serving certificate
  |-- bootstrap kubeconfig certificate
  |-- RHCOS trust bundle

etcd
  |-- peer certificates
  |-- server certificates
  |-- client certificates
  |-- metric certificates

Operators and workloads
  |-- service serving certificates
  |-- webhook certificates
  |-- APIService certificates
  |-- cert-manager issued certificates
  |-- app-specific TLS secrets

External integrations
  |-- corporate proxy CA
  |-- registry CA/server certificate
  |-- LDAP/OIDC/SAML certificates
  |-- Git/CI/CD endpoint certificates
```

A certificate incident should be handled by blast radius:

| Blast radius | Likely certificate area |
|---|---|
| `oc login` fails, API endpoint x509 error | API serving certificate or client trust |
| Console and most routes fail | Ingress wildcard/default certificate |
| Only one app route fails | Route-specific certificate |
| `oc logs`, `oc exec`, `oc rsh` fail | Kubelet serving certificate / CSR |
| Nodes become `NotReady` | Kubelet client certificate / node clock / CSR / API reachability |
| Webhook errors block workloads | Webhook serving cert or stale CA bundle |
| Image pulls fail cluster-wide | Registry certificate or node trust bundle |
| Operators cannot reach internet/proxy endpoints | Proxy/custom CA bundle |
| etcd degraded and API unstable | etcd certs or etcd health |
| OAuth login fails | OAuth route cert, IdP cert, LDAP/OIDC trust, or OAuth pods |

## 3. Common Error Patterns

### 3.1 Expired Certificate

```text
x509: certificate has expired or is not yet valid
certificate has expired
NET::ERR_CERT_DATE_INVALID
curl: (60) SSL certificate problem: certificate has expired
Verify return code: 10 (certificate has expired)
```

Meaning:

- `notAfter` date is in the past, or the client/server time is wrong.

Immediate checks:

```bash
date -u
openssl x509 -in tls.crt -noout -subject -issuer -dates -ext subjectAltName
```

---

### 3.2 Not Yet Valid

```text
x509: certificate has expired or is not yet valid
certificate is not yet valid
```

Meaning:

- `notBefore` is in the future, or node/client clock is behind.

Check time before rotating certificates:

```bash
for n in $(oc get nodes -o name); do
  echo "===== $n ====="
  oc debug "$n" -- chroot /host date -u
  oc debug "$n" -- chroot /host chronyc tracking || true
done
```

---

### 3.3 Unknown Authority

```text
x509: certificate signed by unknown authority
unable to get local issuer certificate
Verify return code: 20 (unable to get local issuer certificate)
```

Meaning:

- CA is not trusted.
- Intermediate chain is missing.
- Wrong trust bundle is mounted.
- Corporate proxy CA changed.

Fix area:

- Add/update CA bundle.
- Fix full chain order.
- Update OpenShift Proxy `trustedCA` or registry `additionalTrustedCA`.

---

### 3.4 Wrong SAN / Hostname

```text
x509: certificate is valid for *.old.example.com, not console.apps.example.com
```

Meaning:

- Certificate does not include requested hostname in SAN.

Fix:

- Reissue certificate with correct DNS SAN.
- Verify SNI is used in `openssl s_client` tests.

---

### 3.5 Bad Certificate / Handshake Failure

```text
remote error: tls: bad certificate
tls: handshake failure
```

Meaning:

- mTLS client cert rejected.
- Wrong key/cert pair.
- Wrong usage/EKU.
- Unsupported TLS/cipher/protocol.
- Peer rejects presented cert chain.

Check:

```bash
openssl x509 -in tls.crt -noout -text | egrep -A2 'Key Usage|Extended Key Usage'
openssl x509 -noout -modulus -in tls.crt | openssl md5
openssl rsa  -noout -modulus -in tls.key | openssl md5
```

## 4. Certificate Ownership Matrix

| Certificate family | Location / object | Owner | Rotation | Troubleshooting action |
|---|---|---|---|---|
| Control plane certs | `openshift-kube-apiserver`, scheduler/controller namespaces | OpenShift | Automatic | Check Operators; use recovery procedure only for rare expiry |
| etcd certs | `openshift-etcd` secrets | OpenShift | Automatic | Check etcd Operator/logs; rotate only via documented method |
| Node/kubelet certs | Node filesystem and CSRs | OpenShift + CSR approval | Automatic, but CSRs may need approval | Inspect `/var/lib/kubelet/pki`; approve valid CSRs |
| Bootstrap cert | `/etc/kubernetes/kubeconfig` | OpenShift | Long-lived | Rarely touched |
| Service CA | `openshift-service-ca/signing-key` | OpenShift | Automatic | Check service-ca Operator; restart stale consumers |
| Service serving certs | Namespace secret named by service annotation | service-ca | Automatic/recreated | Delete generated secret to force reissue |
| API custom certificate | `openshift-config` TLS secret + `apiserver/cluster` | User/admin | User-managed | Renew secret; verify SAN/chain/key |
| Ingress default cert | `openshift-ingress` TLS secret + IngressController | User/admin | User-managed | Renew wildcard/fullchain secret |
| Route cert | Route spec inline cert/key or app secret | App/admin | User-managed | Renew route cert and verify backend cert for reencrypt |
| Proxy CA bundle | `proxy/cluster` + ConfigMap | User/admin/PKI | User-managed | Update trust bundle |
| Registry CA | `image.config.openshift.io/cluster` ConfigMap | User/admin/registry | User-managed | Update registry cert or trusted CA |
| OAuth IdP cert | External IdP + OAuth CA reference | IdP/admin | External/user-managed | Renew external cert or CA bundle |
| Webhook certs | Secret + webhook configuration CA bundle | OLM/service-ca/cert-manager/vendor | Depends | Identify owner and reissue properly |
| cert-manager certs | `Certificate`, `Issuer`, `Order`, `Challenge` | cert-manager + issuer | Automatic if healthy | Check issuer, DNS/HTTP challenge, secret |

## 5. First 15-Minute Triage

### 5.1 Check Platform State

```bash
oc get clusterversion
oc get co
oc get nodes -o wide
oc get csr
oc get pods -A | egrep -i 'crash|error|fail|pending|unknown|terminating'
oc get events -A --sort-by=.lastTimestamp | tail -100
```

### 5.2 Search for TLS Errors

```bash
oc get events -A --sort-by=.lastTimestamp | egrep -i 'x509|cert|certificate|tls|handshake|unknown authority|expired|not yet valid'

oc logs -n openshift-kube-apiserver -l app=openshift-kube-apiserver --tail=200 2>/dev/null | egrep -i 'x509|cert|tls|expired|unknown authority' || true
oc logs -n openshift-authentication -l app=oauth-openshift --tail=200 2>/dev/null | egrep -i 'x509|cert|tls|ldap|oidc|expired|unknown authority' || true
oc logs -n openshift-ingress-operator deployment/ingress-operator --tail=200 2>/dev/null | egrep -i 'x509|cert|tls|expired|unknown authority' || true
oc logs -n openshift-service-ca deployment/service-ca-operator --tail=200 2>/dev/null | egrep -i 'x509|cert|tls|expired|unknown authority' || true
oc logs -n openshift-etcd-operator deployment/etcd-operator --tail=200 2>/dev/null | egrep -i 'x509|cert|tls|expired|unknown authority' || true
```

### 5.3 Check Time Synchronization

```bash
for n in $(oc get nodes -o name); do
  echo "===== $n ====="
  oc debug "$n" -- chroot /host date -u
  oc debug "$n" -- chroot /host chronyc tracking || true
done
```

On a node:

```bash
timedatectl
chronyc tracking
chronyc sources -v
journalctl -u chronyd --no-pager -n 100
```

Never start certificate replacement until clock skew is ruled out.

## 6. API Server Certificate Troubleshooting

### 6.1 Symptoms

```text
Unable to connect to the server: x509: certificate has expired or is not yet valid
Unable to connect to the server: x509: certificate signed by unknown authority
oc login fails
CI/CD kubeconfig fails
```

### 6.2 Inspect API Certificate

```bash
API_HOST="api.ocp4.example.com"
API_PORT="6443"

echo | openssl s_client \
  -connect ${API_HOST}:${API_PORT} \
  -servername ${API_HOST} \
  -showcerts 2>/dev/null \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

Check verification with a CA bundle:

```bash
echo | openssl s_client \
  -connect ${API_HOST}:${API_PORT} \
  -servername ${API_HOST} \
  -CAfile /path/to/ca-bundle.crt \
  -verify_return_error
```

Check for load balancer inconsistency:

```bash
for i in {1..10}; do
  echo "===== attempt $i ====="
  echo | openssl s_client -connect ${API_HOST}:6443 -servername ${API_HOST} 2>/dev/null \
  | openssl x509 -noout -serial -subject -issuer -dates
  sleep 1
done
```

### 6.3 Check OpenShift API Server Config

```bash
oc get apiserver cluster -o yaml
oc get secret -n openshift-config
```

### 6.4 Renew User-Provided API Certificate

Create/update TLS secret:

```bash
oc create secret tls api-custom-cert \
  --cert=/path/to/api-fullchain.crt \
  --key=/path/to/api.key \
  -n openshift-config \
  --dry-run=client -o yaml | oc apply -f -
```

Patch API server if needed:

```bash
oc patch apiserver cluster --type=merge -p '{
  "spec": {
    "servingCerts": {
      "namedCertificates": [
        {
          "names": ["api.ocp4.example.com"],
          "servingCertificate": {"name": "api-custom-cert"}
        }
      ]
    }
  }
}'
```

Watch rollout:

```bash
oc get co kube-apiserver -w
oc get pods -n openshift-kube-apiserver -w
```

Emergency access if trust is the only problem:

```bash
oc --insecure-skip-tls-verify=true login https://api.ocp4.example.com:6443
```

Use this only as a temporary break-glass method.

## 7. Ingress / Router Certificate Troubleshooting

### 7.1 Symptoms

```text
Console route certificate expired
All routes show browser certificate warning
curl: (60) SSL certificate problem
OAuth route certificate expired
```

### 7.2 Inspect Route Certificate

```bash
HOST="console-openshift-console.apps.ocp4.example.com"

echo | openssl s_client \
  -connect ${HOST}:443 \
  -servername ${HOST} \
  -showcerts 2>/dev/null \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 7.3 Check IngressController Default Certificate

```bash
oc get ingresscontroller default -n openshift-ingress-operator -o yaml | sed -n '/defaultCertificate:/,+5p'
oc get secret -n openshift-ingress
```

Decode current secret:

```bash
oc get secret -n openshift-ingress <secret-name> -o jsonpath='{.data.tls\.crt}' \
| base64 -d \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 7.4 Renew Custom Default Ingress Certificate

Requirements:

- Wildcard SAN like `*.apps.ocp4.example.com`.
- Full chain in correct order.
- Unencrypted private key.
- Secret in `openshift-ingress` namespace.

Create/update secret:

```bash
oc create secret tls apps-wildcard-cert \
  --cert=/path/to/apps-fullchain.crt \
  --key=/path/to/apps.key \
  -n openshift-ingress \
  --dry-run=client -o yaml | oc apply -f -
```

Patch IngressController:

```bash
oc patch ingresscontroller.operator default \
  -n openshift-ingress-operator \
  --type=merge \
  -p '{"spec":{"defaultCertificate":{"name":"apps-wildcard-cert"}}}'
```

Watch:

```bash
oc get co ingress -w
oc get pods -n openshift-ingress -w
oc logs -n openshift-ingress deployment/router-default --tail=100
```

Senior note:

- If the secret name stays the same and only data changes, router can hot-reload in many cases.
- If traffic still shows an old certificate, check external load balancer, WAF, CDN, or HAProxy/F5 termination.

## 8. Route-Specific Certificate Troubleshooting

### 8.1 Inspect Route TLS

```bash
oc get route <route-name> -n <namespace> -o yaml
oc get route <route-name> -n <namespace> -o jsonpath='{.spec.tls.certificate}' \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 8.2 Edge Route Renewal

```bash
oc create route edge <route-name> \
  --service=<service-name> \
  --hostname=<fqdn> \
  --cert=/path/to/fullchain.crt \
  --key=/path/to/tls.key \
  -n <namespace> \
  --dry-run=client -o yaml | oc apply -f -
```

Or safely edit:

```bash
oc get route <route-name> -n <namespace> -o yaml > route-backup.yaml
oc edit route <route-name> -n <namespace>
```

### 8.3 Reencrypt Route

For `reencrypt`, there are two TLS areas:

1. Client to router certificate.
2. Router to backend service certificate and destination CA.

Check both:

```bash
oc get route <route-name> -n <namespace> -o yaml | sed -n '/tls:/,$p'
oc get endpoints <service-name> -n <namespace>
```

If backend app certificate expired, route renewal alone will not fix the issue.

## 9. Kubelet / Node Certificate Troubleshooting

### 9.1 Symptoms

```text
Node NotReady
oc logs fails
oc exec fails
oc rsh fails
error dialing backend
x509 error connecting to node:10250
```

### 9.2 Check CSRs

```bash
oc get csr
oc get csr -o custom-columns=NAME:.metadata.name,AGE:.metadata.creationTimestamp,SIGNER:.spec.signerName,REQUESTOR:.spec.username,CONDITION:.status.conditions[*].type
oc describe csr <csr-name>
```

Approve only valid CSRs:

```bash
oc adm certificate approve <csr-name>
```

Validation before approval:

- Requestor is expected.
- Node name matches a real node.
- Signer name is expected.
- Usages and SANs make sense.
- Node is not rogue.

### 9.3 Inspect Node Certificates

```bash
oc debug node/<node-name>
chroot /host
openssl x509 -in /var/lib/kubelet/pki/kubelet-client-current.pem -noout -subject -issuer -dates
openssl x509 -in /var/lib/kubelet/pki/kubelet-server-current.pem -noout -subject -issuer -dates
exit
exit
```

Loop all nodes:

```bash
for n in $(oc get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'); do
  echo "===== $n client ====="
  oc debug node/$n -- chroot /host openssl x509 -in /var/lib/kubelet/pki/kubelet-client-current.pem -noout -subject -issuer -dates 2>/dev/null || true
  echo "===== $n server ====="
  oc debug node/$n -- chroot /host openssl x509 -in /var/lib/kubelet/pki/kubelet-server-current.pem -noout -subject -issuer -dates 2>/dev/null || true
done
```

### 9.4 Kubelet CA Certificate

```bash
oc -n openshift-kube-apiserver-operator get secret kube-apiserver-to-kubelet-signer \
  -o jsonpath='{.metadata.annotations.auth\.openshift\.io/certificate-not-after}{"\n"}'

oc -n openshift-kube-apiserver-operator get secret kube-apiserver-to-kubelet-signer \
  -o jsonpath='{.data.tls\.crt}' \
| base64 -d \
| openssl x509 -noout -subject -issuer -dates
```

Manual renewal trigger, only when required:

```bash
oc annotate -n openshift-kube-apiserver-operator \
  secret kube-apiserver-to-kubelet-signer \
  auth.openshift.io/certificate-not-after-
```

### 9.5 Restart Kubelet Only If Needed

```bash
oc debug node/<node-name> -- chroot /host systemctl restart kubelet
oc get nodes -w
```

Do not delete kubelet PKI files unless following a validated recovery process.

## 10. Service CA and Service Serving Certificates

### 10.1 Concepts

The service-ca Operator issues service serving certificates for internal service DNS names. Services request a cert by annotation:

```bash
oc annotate service <service-name> \
  service.beta.openshift.io/serving-cert-secret-name=<secret-name> \
  -n <namespace>
```

The generated certificate is valid for internal service names such as:

```text
<service>.<namespace>.svc
<service>.<namespace>.svc.cluster.local
```

For headless services, wildcard subjects can be generated. Do not use service-ca when clients must identify individual pods separately.

### 10.2 Check Service CA

```bash
oc get co service-ca
oc get pods -n openshift-service-ca
oc logs -n openshift-service-ca deployment/service-ca-operator --tail=200

oc get secrets/signing-key -n openshift-service-ca \
  -o template='{{index .data "tls.crt"}}' \
| base64 --decode \
| openssl x509 -noout -subject -issuer -dates
```

### 10.3 Check Service Serving Certificate

```bash
NS="my-namespace"
SVC="my-service"

oc describe service $SVC -n $NS | grep -i serving-cert-secret-name
SECRET=$(oc get svc $SVC -n $NS -o jsonpath='{.metadata.annotations.service\.beta\.openshift\.io/serving-cert-secret-name}')

echo "Secret: $SECRET"

oc get secret $SECRET -n $NS -o jsonpath='{.data.tls\.crt}' \
| base64 -d \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 10.4 Force Service Serving Certificate Reissue

```bash
oc delete secret <serving-cert-secret-name> -n <namespace>
oc get secret <serving-cert-secret-name> -n <namespace> -w
```

Restart affected pods if the app does not reload certificates dynamically:

```bash
oc rollout restart deployment/<deployment-name> -n <namespace>
```

### 10.5 Check Injected Service CA Bundles

```bash
oc get configmap -A -o json \
| jq -r '.items[] | select(.metadata.annotations["service.beta.openshift.io/inject-cabundle"]=="true") | [.metadata.namespace,.metadata.name] | @tsv'
```

Inspect bundle:

```bash
oc get configmap <cm-name> -n <namespace> -o jsonpath='{.data.service-ca\.crt}' \
| openssl x509 -noout -subject -issuer -dates
```

For webhook/APIService issues, also check:

```bash
oc get apiservice
oc get apiservice <name> -o yaml | sed -n '/caBundle:/,+3p'
oc get validatingwebhookconfiguration <name> -o yaml | grep -A5 caBundle
oc get mutatingwebhookconfiguration <name> -o yaml | grep -A5 caBundle
```

## 11. etcd Certificate Troubleshooting

### 11.1 Symptoms

```text
etcd ClusterOperator Degraded=True
API unavailable or unstable
context deadline exceeded
remote error: tls: bad certificate
etcd member unhealthy
```

### 11.2 First Checks

```bash
oc get co etcd
oc get pods -n openshift-etcd -o wide
oc logs -n openshift-etcd-operator deployment/etcd-operator --tail=300
```

Check TLS errors in etcd pods:

```bash
for p in $(oc get pods -n openshift-etcd -l app=etcd -o name); do
  echo "===== $p ====="
  oc logs -n openshift-etcd $p -c etcd --tail=200 | egrep -i 'x509|tls|cert|expire|bad certificate|unknown authority' || true
done
```

### 11.3 Check etcd Signer

```bash
oc get secret -n openshift-etcd etcd-signer -o jsonpath='{.data.tls\.crt}' \
| base64 -d \
| openssl x509 -noout -subject -issuer -dates
```

### 11.4 Manual Signer Rotation, Only If Needed

```bash
oc get secret -n openshift-etcd etcd-signer -oyaml > signer_backup_secret.yaml
oc delete secret -n openshift-etcd etcd-signer
oc get co etcd -w
oc get pods -n openshift-etcd -w
```

Safety rules:

- Take an etcd backup before risky actions when possible.
- Do not rotate certificates during quorum loss without support guidance.
- Do not restore from stale backups casually.
- Do not delete multiple etcd-related secrets blindly.

## 12. Proxy, Corporate CA, and External Registry Trust

### 12.1 Proxy CA Symptoms

```text
Operators cannot reach external HTTPS endpoints
CatalogSource fails
image pulls fail
x509: certificate signed by unknown authority
x509: certificate has expired or is not yet valid
```

### 12.2 Check Cluster Proxy

```bash
oc get proxy cluster -o yaml
oc get proxy cluster -o jsonpath='{.spec.trustedCA.name}{"\n"}'
oc get configmap -n openshift-config <trusted-ca-configmap> -o yaml
```

### 12.3 Update Runtime Trusted CA

```bash
oc create configmap user-ca-bundle \
  --from-file=ca-bundle.crt=/path/to/corporate-ca-bundle.crt \
  -n openshift-config \
  --dry-run=client -o yaml | oc apply -f -

oc patch proxy/cluster --type=merge -p '{"spec":{"trustedCA":{"name":"user-ca-bundle"}}}'
```

Watch:

```bash
oc get co
oc get mcp
```

### 12.4 Check Registry Certificate from a Node

```bash
oc debug node/<node>
chroot /host
openssl s_client -connect registry.example.com:443 -servername registry.example.com -showcerts </dev/null
curl -vk https://registry.example.com/v2/
exit
exit
```

### 12.5 Configure Additional Trusted CA for Registry

```bash
oc create configmap registry-cas -n openshift-config \
  --from-file=registry.example.com..443=/path/to/registry-ca.crt \
  --dry-run=client -o yaml | oc apply -f -

oc patch image.config.openshift.io/cluster --type=merge \
  -p '{"spec":{"additionalTrustedCA":{"name":"registry-cas"}}}'
```

Watch MachineConfigPool if node trust is updated:

```bash
oc get mcp -w
oc describe mcp worker
```

## 13. OAuth / LDAP / OIDC Certificate Issues

### 13.1 Symptoms

```text
Users cannot log in
OAuth pods log x509 errors
LDAP bind/search fails over TLS
OIDC discovery endpoint fails
```

### 13.2 Check OAuth

```bash
oc get oauth cluster -o yaml
oc get co authentication
oc get pods -n openshift-authentication
oc logs -n openshift-authentication -l app=oauth-openshift --tail=300 | egrep -i 'x509|tls|ldap|oidc|certificate|unknown authority|expired'
```

### 13.3 Check External IdP Certificate

LDAP over TLS:

```bash
openssl s_client -connect ldap.example.com:636 -servername ldap.example.com -showcerts </dev/null \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

OIDC endpoint:

```bash
openssl s_client -connect idp.example.com:443 -servername idp.example.com -showcerts </dev/null \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 13.4 Fix

- Renew external IdP certificate on the IdP side.
- If CA changed, update the CA ConfigMap referenced in OAuth IdP config.
- Restart OAuth pods if required:

```bash
oc delete pod -n openshift-authentication -l app=oauth-openshift
oc get co authentication -w
```

Senior warning:

> Do not remove `kubeadmin` or your break-glass admin identity until IdP login is verified.

## 14. Webhook and APIService Certificate Issues

### 14.1 Symptoms

```text
Internal error occurred: failed calling webhook
conversion webhook failed
x509: certificate has expired or is not yet valid
x509: certificate signed by unknown authority
```

### 14.2 Identify the Failing Webhook

```bash
oc get validatingwebhookconfiguration
oc get mutatingwebhookconfiguration
oc get apiservice | grep False
```

From the error message, inspect the exact object:

```bash
oc get validatingwebhookconfiguration <name> -o yaml
oc get mutatingwebhookconfiguration <name> -o yaml
oc get apiservice <name> -o yaml
```

### 14.3 Check Webhook Service and Secret

```bash
oc get svc -A | grep <webhook-service>
oc get endpoints -n <ns> <webhook-service>
oc describe svc -n <ns> <webhook-service>
oc get secret -n <ns>

oc get secret <secret> -n <ns> -o jsonpath='{.data.tls\.crt}' \
| base64 -d \
| openssl x509 -noout -subject -issuer -dates -ext subjectAltName
```

### 14.4 Fix by Ownership

| Owner | Fix |
|---|---|
| service-ca | Delete generated serving cert secret and restart webhook pods |
| OLM | Check CSV/Subscription/InstallPlan/OLM pods; allow OLM to reconcile |
| cert-manager | Check `Certificate`, `CertificateRequest`, `Issuer`, `Order`, `Challenge` |
| Vendor Operator | Follow vendor docs |
| Manually managed | Renew secret and update webhook CA bundle |

Emergency mitigation, only with approval:

```bash
oc patch validatingwebhookconfiguration <name> --type='json' \
  -p='[{"op":"replace","path":"/webhooks/0/failurePolicy","value":"Ignore"}]'
```

Restore the original failure policy after fixing. This is a break-glass action because it can weaken admission control.

## 15. Cluster-Wide TLS Secret Audit Scripts

### 15.1 List TLS Secrets and Expiry

```bash
#!/usr/bin/env bash
set -euo pipefail

for ns in $(oc get ns -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'); do
  for sec in $(oc get secret -n "$ns" -o jsonpath='{range .items[?(@.data.tls\.crt)]}{.metadata.name}{"\n"}{end}' 2>/dev/null || true); do
    crt=$(oc get secret "$sec" -n "$ns" -o jsonpath='{.data.tls\.crt}' 2>/dev/null || true)
    [ -z "$crt" ] && continue
    echo "===== $ns/$sec ====="
    echo "$crt" | base64 -d 2>/dev/null | openssl x509 -noout -subject -issuer -dates 2>/dev/null || echo "Unable to parse certificate"
  done
done
```

### 15.2 Show TLS Secrets Expiring in 30 Days

```bash
#!/usr/bin/env bash
set -euo pipefail

DAYS=${1:-30}
SECONDS_LEFT=$((DAYS*24*60*60))
NOW=$(date +%s)

for ns in $(oc get ns -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'); do
  for sec in $(oc get secret -n "$ns" -o jsonpath='{range .items[?(@.data.tls\.crt)]}{.metadata.name}{"\n"}{end}' 2>/dev/null || true); do
    crt=$(oc get secret "$sec" -n "$ns" -o jsonpath='{.data.tls\.crt}' 2>/dev/null || true)
    [ -z "$crt" ] && continue
    enddate=$(echo "$crt" | base64 -d 2>/dev/null | openssl x509 -noout -enddate 2>/dev/null | cut -d= -f2- || true)
    [ -z "$enddate" ] && continue
    end_epoch=$(date -d "$enddate" +%s 2>/dev/null || true)
    [ -z "$end_epoch" ] && continue
    remaining=$((end_epoch - NOW))
    if [ "$remaining" -le "$SECONDS_LEFT" ]; then
      echo "$ns/$sec expires at $enddate"
    fi
  done
done
```

### 15.3 External Endpoint Probe

```bash
#!/usr/bin/env bash
set -euo pipefail

HOST=$1
PORT=${2:-443}
WARN_DAYS=${3:-30}

enddate=$(echo | openssl s_client -connect ${HOST}:${PORT} -servername ${HOST} 2>/dev/null \
  | openssl x509 -noout -enddate | cut -d= -f2-)
end_epoch=$(date -d "$enddate" +%s)
now=$(date +%s)
left_days=$(( (end_epoch - now) / 86400 ))

echo "$HOST:$PORT expires in $left_days days at $enddate"

if [ "$left_days" -lt "$WARN_DAYS" ]; then
  exit 2
fi
```

Usage:

```bash
./check-endpoint-cert.sh api.ocp4.example.com 6443 30
./check-endpoint-cert.sh console-openshift-console.apps.ocp4.example.com 443 30
./check-endpoint-cert.sh registry.example.com 443 30
./check-endpoint-cert.sh ldap.example.com 636 30
```

## 17. Certificate Renewal Production Checklist

Before renewal:

- [ ] Identify certificate owner.
- [ ] Confirm exact endpoint and SNI hostname.
- [ ] Confirm required SANs.
- [ ] Confirm key matches certificate.
- [ ] Confirm full chain order.
- [ ] Confirm certificate is currently valid and not future-dated.
- [ ] Confirm CA is trusted by target clients.
- [ ] Confirm correct namespace and secret name.
- [ ] Back up existing object YAML.
- [ ] Prepare rollback secret/config.
- [ ] Schedule maintenance if API/router/OAuth impact is possible.
- [ ] Notify application and security teams.

Validate cert and key:

```bash
openssl x509 -noout -modulus -in tls.crt | openssl md5
openssl rsa  -noout -modulus -in tls.key | openssl md5
```

For ECDSA/private keys:

```bash
openssl x509 -noout -pubkey -in tls.crt | openssl sha256
openssl pkey -pubout -in tls.key | openssl sha256
```

Validate certificate:

```bash
openssl x509 -in tls.crt -noout -subject -issuer -dates -ext subjectAltName
openssl verify -CAfile root-and-intermediate-ca.crt tls.crt
```

After renewal:

- [ ] Verify endpoint with `openssl s_client`.
- [ ] Verify `oc login`.
- [ ] Verify console login.
- [ ] Verify sample application route.
- [ ] Verify `oc get co` is healthy.
- [ ] Verify image pull if registry/proxy trust changed.
- [ ] Verify webhooks if service certificates changed.
- [ ] Verify monitoring alerts are clearing.
- [ ] Record new expiry date in inventory/CMDB.

## 18. Prevention and Monitoring Strategy

Recommended warning thresholds:

| Remaining validity | Action |
|---:|---|
| 90 days | Open renewal ticket |
| 60 days | Confirm owner and renewal path |
| 30 days | Renewal should be scheduled |
| 14 days | Escalate to platform lead |
| 7 days | Daily tracking / incident risk |
| < 24 hours | Emergency renewal |

Monitor:

- API endpoint certificate expiry.
- Default ingress wildcard certificate expiry.
- Critical route-specific certificates.
- User-managed TLS secrets.
- Webhook service certificates.
- External registry certificate.
- LDAP/OIDC/SAML endpoint certificate.
- Corporate proxy CA expiry.
- Pending CSRs.
- `ClusterOperator` degraded conditions containing TLS errors.
- cert-manager `Certificate` readiness and expiration.

Operational best practices:

1. Maintain a certificate inventory for all platform and critical app endpoints.
2. Use stable secret names and update secret contents where possible.
3. Monitor from outside and inside the cluster.
4. Coordinate with enterprise PKI before expiry windows.
5. Keep etcd backups current.
6. Never bulk-approve CSRs without validating identity.
7. Do not manually edit system-managed secrets.
8. Restart workloads that do not reload mounted certs or trust bundles.
9. Keep break-glass admin access tested.
10. Document rollback steps before applying certificate changes.

## 19. Exam / Interview Troubleshooting Scenarios

### Scenario 1: `oc logs` and `oc exec` Fail but Pods Are Running

Likely cause:

- Kubelet serving certificate CSR pending or invalid.

Commands:

```bash
oc get csr
oc describe csr <csr-name>
oc adm certificate approve <csr-name>
oc logs <pod> -n <namespace>
```

Also check:

```bash
oc get nodes
oc adm node-logs <node-name> -u kubelet --tail=100
```

---

### Scenario 2: Console Certificate Expired but API Works

Likely cause:

- Ingress default wildcard certificate expired.

Commands:

```bash
oc get ingresscontroller default -n openshift-ingress-operator -o yaml
oc get secret -n openshift-ingress <secret> -o jsonpath='{.data.tls\.crt}' \
| base64 -d | openssl x509 -noout -dates -subject -issuer
```

Fix:

```bash
oc create secret tls apps-wildcard-cert --cert=fullchain.crt --key=tls.key -n openshift-ingress --dry-run=client -o yaml | oc apply -f -
oc patch ingresscontroller.operator default -n openshift-ingress-operator --type=merge -p '{"spec":{"defaultCertificate":{"name":"apps-wildcard-cert"}}}'
```

---

### Scenario 3: Pods Cannot Pull from Private Registry

Likely cause:

- Registry certificate expired or registry CA untrusted by nodes.

Commands:

```bash
oc describe pod <pod> -n <namespace>
oc debug node/<node> -- chroot /host curl -vk https://registry.example.com/v2/
oc get image.config.openshift.io/cluster -o yaml
```

Fix:

- Renew registry server certificate.
- Update `additionalTrustedCA` if the CA changed.

---

### Scenario 4: Operator CR Creation Fails with Webhook x509 Error

Likely cause:

- Webhook serving certificate expired or `caBundle` stale.

Commands:

```bash
oc get validatingwebhookconfiguration <name> -o yaml
oc get svc -n <namespace> <webhook-service>
oc get secret -n <namespace> <webhook-secret> -o jsonpath='{.data.tls\.crt}' \
| base64 -d | openssl x509 -noout -dates -subject -issuer
```

Fix:

- Reissue webhook cert based on owner: service-ca, OLM, cert-manager, vendor, or manual.
- Restart webhook pods.
- Refresh CA bundle.

## 21. Key Version-Aware Notes

Always check the documentation for the exact OpenShift version running in production. Current OpenShift 4 documentation describes these important behaviors:

- User-provided API certificates are managed by the user/admin.
- User-provided default ingress certificates are managed by the user/admin.
- Service CA is system-managed and rotates automatically, but stale consumers may need restart.
- Service serving certificates can be manually reissued by deleting the generated secret.
- Kubelet/node certificates use CSR-based rotation and may require manual CSR approval in some environments.
- etcd certificates are system-managed and rotate automatically, but manual rotation has a documented process.
- Control plane certificates are system-managed and automatically rotated; expired control-plane recovery is a special recovery scenario.
- Proxy/custom CA certificates and trust bundles are user/admin lifecycle items; OpenShift does not monitor external CA expiry for you.

## 23. Final Practical Advice

In real production incidents, certificate expiry is rarely fixed by only replacing a file. You must validate the complete chain:

```text
Correct endpoint -> correct certificate -> correct SAN -> correct chain -> correct key -> correct trust bundle -> correct pod/router reload -> healthy Operator status
```

A 10-year experienced OpenShift administrator does not start by deleting secrets. They start by identifying ownership, blast radius, expiry date, trust chain, and rotation mechanism. That approach prevents turning a certificate warning into a full cluster outage.
